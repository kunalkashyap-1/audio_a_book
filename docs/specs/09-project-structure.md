# 09. Project Structure

## 1. What the structure has to guarantee

| # | Guarantee | Mechanism |
|---|---|---|
| S1 | Vendor SDKs cannot leak outside `aab_providers` | package layout and review at launch; import-linter in CI at target |
| S2 | Only one layer writes SQL | `aab_db` is the only importer of `sqlalchemy`; enforced by review and a grep test at target |
| S3 | Domain packages are testable without a database | dependency direction, plain dataclasses — already true |
| S4 | Web types cannot drift from the API | `openapi.json` → `api.d.ts` generated in one command; the web app imports only `@aab/contracts`, and `tsc` fails on drift |
| S5 | Two entrypoints, one codebase | `services/api` and `services/worker` import the same packages; one container image at target |
| S6 | A new contributor can find the right file in under a minute | the table in §3 and the tree in §2 |

Everything below is enforced by a tool or it is decoration.

### 2.1 Target additions (absent at launch)

- `python/src/aab_prompts/` — prompt bundles and JSON schemas, once an LLM adapter exists.
- `python/src/aab_db/migrations/` — Alembic, once the target database is Postgres.
- `apps/mobile/`, `infra/`, `evals/`.

Spec 02's `repositories/` layer is `aab_db` here. It sits beside the schema because the SQL
and the DDL change together, and both entrypoints call it.

## 3. Package responsibilities

| Package | Owns | May import | Must not import |
|---|---|---|---|
| `aab_core` | ids, errors, result types, clock, hashing, settings schema | stdlib | everything else |
| `aab_db` | SQLAlchemy models, repositories, Alembic | `aab_core` | `aab_providers`, `services.*` |
| `aab_ingest` | format detection, parsers, normalisation, chapter detection | `aab_core` | `aab_db`, `aab_providers` |
| `aab_story` | attribution rules, character merging, scene detection | `aab_core`, `aab_prompts` | `aab_db`, `aab_providers` |
| `aab_prompts` | prompt text, JSON schemas, validators | `aab_core` | providers, db |
| `aab_tts` | segmentation, render key, render plans | `aab_core` | `aab_db`, `aab_providers` |
| `aab_audio` | ffmpeg invocation, QC, mastering, manifests | `aab_core` | `aab_db`, `aab_providers` |
| `aab_providers` | vendor SDKs, adapters, capability probes, estimates | `aab_core` | `aab_db`, any `services.*` |
| `aab_jobs` | claim/lease/retry, priority, scheduling helpers | `aab_core`, `aab_db` | `aab_providers` |
| `services/api` | HTTP, auth, authorisation, use cases | all of the above | — |
| `services/worker` | job execution, wiring | all of the above | `services/api` |

The rule that matters: **domain packages take plain dataclasses in and out.** `aab_tts` does
not know what a `Session` is. That is what makes the render key testable in a unit test with
no fixtures and no database.

## 4. Enforcement

### 4.1 Import-linter

```toml
# python/pyproject.toml
[tool.importlinter]
root_packages = ["aab_core", "aab_db", "aab_ingest", "aab_story", "aab_prompts",
                 "aab_tts", "aab_audio", "aab_providers", "aab_jobs"]

[[tool.importlinter.contracts]]
name = "Domain packages do not depend on persistence"
type = "forbidden"
source_modules = ["aab_ingest", "aab_story", "aab_tts", "aab_audio", "aab_providers"]
forbidden_modules = ["aab_db", "sqlalchemy", "alembic"]

[[tool.importlinter.contracts]]
name = "Vendor SDKs only inside aab_providers"
type = "forbidden"
source_modules = ["aab_core", "aab_db", "aab_ingest", "aab_story", "aab_prompts",
                  "aab_tts", "aab_audio", "aab_jobs"]
forbidden_modules = ["openai", "anthropic", "google.genai", "boto3", "httpx"]

[[tool.importlinter.contracts]]
name = "Core is a leaf"
type = "forbidden"
source_modules = ["aab_core"]
forbidden_modules = ["aab_db", "aab_ingest", "aab_story", "aab_prompts", "aab_tts",
                     "aab_audio", "aab_providers", "aab_jobs"]
```

`httpx` is on the forbidden list because a raw HTTP call to a provider is the same violation
as importing its SDK, only harder to find.

### 4.2 SQL boundary

All database access goes through `aab_db.repositories`. Two checks:

- import-linter forbids `sqlalchemy` in domain packages.
- A test walks `services/` and `python/aab_*` (excluding `aab_db`) and fails on
  `select(`, `text(`, `session.execute(`.

### 4.3 Private-schema boundary

Every query touching `private.*` must live in `aab_db/repositories/private_*.py`. A CI grep
fails the build if `private.` appears elsewhere outside migrations and tests. The repository
functions take `actor: AuthenticatedUser` as their first argument, so the `owner_id` predicate
cannot be forgotten.

### 4.4 Frontend types

`packages/contracts` holds generated artefacts. `openapi.json` and `src/api.d.ts` are produced,
never hand-edited; only `src/index.ts` (the friendly alias exports) is maintained by hand. The
workspace uses npm because `pnpm`/`corepack` are not available on the target machines:

```bash
# FastAPI → OpenAPI → TypeScript
./scripts/generate_contracts.sh      # = export_openapi.py + npm run contracts:generate
npm run typecheck                    # fails if the web app uses a stale shape
npm run build
```

`export_openapi.py` builds the app with an in-memory SQLite database and the fake provider, so
exporting touches no real data and needs no model weights. CI should also fail if regeneration
produces a diff. Hand-written duplicates of API types are rejected in review with a link to
this paragraph.

## 5. Python conventions

### 5.1 Tooling

| Tool | Purpose | Config |
|---|---|---|
| `uv` | workspace, lockfile, virtualenv | `python/pyproject.toml` |
| `ruff` | lint + format | line length 100, `E,F,I,UP,B,SIM,ASYNC,S,RUF` |
| `mypy` | types | `strict = true` for `aab_core`, `aab_tts`, `aab_ingest`; `basic` elsewhere |
| `pytest` | tests | `-q --strict-markers` |
| `import-linter` | boundaries | §4.1 |

`mypy --strict` is required exactly where a bug is silent and expensive: the render key, the
parsers, and the core types. Enforcing strict mode on the API layer buys annotations, not
safety.

### 5.2 Structure inside a package

```
aab_tts/
├── pyproject.toml
├── src/aab_tts/
│   ├── __init__.py
│   ├── key.py             # render_key, canonical_bytes
│   ├── segment.py         # segmentation rules
│   ├── plan.py            # RenderPlan, batching
│   └── errors.py
└── tests/
    ├── test_key_golden.py
    ├── test_key_sensitivity.py
    └── test_segment.py
```

`src/` layout so tests import the installed package, not a directory that happens to be on
`sys.path` — this catches packaging errors locally instead of in the container.

### 5.3 Errors

```python
class AabError(Exception):
    code: str                 # stable, documented, in the error registry
    http_status: int = 500
    retryable: bool = False

class NotFound(AabError): code = "not_found"; http_status = 404
class Forbidden(AabError): code = "forbidden"; http_status = 404   # 404, not 403
class BudgetExceeded(AabError): code = "budget_exceeded"; http_status = 429
```

API responses are RFC 9457 `application/problem+json`. Provider errors (spec 04) are mapped
into this hierarchy at the job boundary; they never escape to HTTP raw.

### 5.4 IDs and time

- Prefixed ULIDs: `wk_01JB8Z0C`, `rev_...`, `sg_...`. Sortable, opaque, greppable in logs.
- All timestamps `timestamptz`, UTC, ISO-8601 with `Z` on the wire.
- Durations in integer milliseconds. Never floats.

## 6. TypeScript conventions

| Concern | Decision |
|---|---|
| Framework | Next.js App Router, React Server Components where they help first paint |
| Data fetching | server components call the API directly; client uses `fetch` with the SDK types |
| State | none global; `useState` + URL state. A book player does not need Redux |
| Styling | Tailwind + `packages/ui` primitives |
| Validation | zod schemas generated from OpenAPI; parse at the boundary |
| Auth | Cognito hosted UI or embedded; token in memory + refresh cookie |
| Player | `<audio>` for MVP; Media3 on Android; no HLS.js unless we actually segment |

Mobile shares `packages/contracts` and `packages/ui` tokens, not components that assume a
browser.

## 7. Where does this code go?

| Task | Location |
|---|---|
| New HTTP endpoint | `services/api/app/routes/` + a service method |
| Business rule (who may do what) | `services/api/app/services/` |
| New SQL query | `python/aab_db/repositories/` |
| New table | `python/aab_db/migrations/` + model |
| EPUB quirk | `python/aab_ingest/` |
| Attribution heuristic | `python/aab_story/` |
| Prompt wording | `python/aab_prompts/prompts/*.md` |
| Render key field | `python/aab_tts/key.py` + ADR-0004 + golden test |
| ffmpeg filter chain | `python/aab_audio/master.py` |
| New provider | `python/aab_providers/<vendor>/` |
| New job kind | `services/worker/worker/jobs/<kind>.py` + `aab_jobs` registration |
| Admin page | `apps/web/app/admin/page.tsx` (tabbed UI) + `api.admin*` in `apps/web/lib/api.ts` |
| Config flag | `ops.feature_flags` row + `packages/config` key |

If a task does not fit one row, the design is unclear — write it down before writing code.

## 8. Testing layout

| Layer | Location | Runs | Budget |
|---|---|---|---|
| Unit | `python/*/tests`, `apps/web/**/*.test.ts` | every push | 60 s |
| Contract | `packages/contracts/tests` | every push | 10 s |
| Integration | `services/*/tests/integration` | every push, Postgres service container | 3 min |
| E2E | `apps/web/e2e` | PRs to `main` | 3 min |
| Evaluation | `evals/` | nightly + release | 20 min |

Rules:

- Integration tests use a real Postgres and a fake S3 (`moto` or MinIO). Mocking the database
  tests the mock.
- Provider tests use recorded fixtures plus a fake provider; the real API is never called in
  CI.
- Every fixed bug gets a test that fails on the previous commit.
- `evals/` is not in the CI critical path because it costs money; it runs nightly and blocks
  releases.

## 9. CI

```yaml
# .github/workflows/ci.yml (shape)
jobs:
  lint:        ruff check, ruff format --check, eslint, tsc --noEmit
  boundaries:  lint-imports, SQL grep, private-schema grep, contracts drift
  unit:        pytest -m "not integration" -q --cov
  integration: services: postgres:16, minio; pytest -m integration
  e2e:         docker compose up -d; playwright test
  build:       docker build (two targets: api, worker)
  deploy:      on main: push image, ssh, docker compose up -d, health check
```

Time budget: under 10 minutes from push to green, using uv and pnpm caches. A CI that takes
20 minutes gets bypassed.

Deploy is intentionally dull: build image, `docker compose up -d api worker scheduler`,
migrate, health check, roll back on failure by re-tagging the previous image. No blue/green at
MVP — the API is stateless and the worker drains via lease expiry.

```bash

uv run python -m scripts.seed_dev          # 1 book, 1 voice, 3 chapters

```

`PROVIDERS=fake` is the default locally: deterministic sine-wave "speech" with the right
durations, so the player, manifests and cache logic can be developed with no GPU and no spend.
Real providers are opt-in via `PROVIDERS=real` and a personal key.

## 11. Configuration

- Settings are a Pydantic model, loaded from environment, validated at startup, and the
  process refuses to boot if a required value is missing.
- `.env.example` is the canonical list and is updated in the same commit as the field.
- Secrets never appear in environment variables in production; `auth_ref` points at an SSM
  parameter, fetched once at boot and refreshed on rotation.
- Behavioural configuration (routing, flags, budgets, prices) is **not** environment
  configuration. It lives in the database and is editable at runtime (ADR-0005).

## 12. Repository hygiene

- Conventional commits (`feat:`, `fix:`, `docs:`, `perf:`, `chore:`).
- PR template asks three questions: does this change a render key? does this change a
  provider boundary? does this add a dependency with an unreviewed licence?
- `git init` is the first Phase 1 task; the current tree is unstaged work.
- Generated files (`openapi.json`, `schema.ts`) are committed so diffs show contract changes,
  and CI asserts they match the generator output.
- `docs/` changes ride with code changes that contradict them. A spec that has drifted is a
  bug in the spec.
